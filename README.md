# دليل الاستيوارد — Marriott Stewarding Guide

تطبيق ويب تقدّمي (PWA) ثابت بالكامل (Static) لقسم الـ Stewarding — مرجع
المواد الكيميائية، أكاديمية سلامة الغذاء (HACCP والقواعد الذهبية)، السلامة
والطوارئ، ومساعد ذكي محلي، مصمم للعمل بالكامل بدون إنترنت بعد أول زيارة.

**HTML + CSS + Vanilla JavaScript (ES Modules) فقط.** لا خادم، لا Node.js،
لا أدوات بناء (build tools)، لا أطر عمل (frameworks). يعمل مباشرة عند فتح
`index.html` محلياً أو عند رفعه على GitHub Pages بدون أي إعداد إضافي.

---

## 🚀 التشغيل

### محلياً (فتح مباشر)
افتح `index.html` مباشرة في أي متصفح حديث. كل شيء يعمل ماعدا عامل الخدمة
(Service Worker) والذي يتطلب بروتوكول `https://` أو `http://localhost` —
هذا قيد أمني من تصميم كل المتصفحات وليس خللاً في التطبيق. بدون عامل الخدمة
يعمل التطبيق بشكل طبيعي تماماً، فقط بدون دعم "التثبيت" أو التخزين المؤقت
الكامل بدون إنترنت.

### محلياً (خادم تطوير بسيط — اختياري، للاختبار الكامل لميزات PWA)
```bash
python3 -m http.server 8000
# ثم افتح http://localhost:8000
```

### على GitHub Pages (الإنتاج)
1. ارفع محتويات هذا المجلد بالكامل لمستودع GitHub.
2. من إعدادات المستودع → **Pages** → اختر الفرع (Branch) والمجلد الجذر (`/`).
3. لا حاجة لأي خطوة بناء (build step) — الملفات تعمل كما هي مباشرة.

## 🏗️ البنية المعمارية

```
/
├── index.html              ← الصدفة الوحيدة (SPA Shell) — بلا محتوى تطبيقي فعلي
├── manifest.json           ← بيان PWA (اسم، أيقونات، اختصارات)
├── service-worker.js       ← استراتيجية التخزين المؤقت (Cache First)
├── README.md
│
├── assets/
│   ├── css/
│   │   ├── tokens.css      ← توكنز التصميم (الألوان، المسافات، الخطوط..) — المصدر الوحيد للحقيقة
│   │   ├── base.css        ← إعادة تأسيس + عناصر HTML أساسية + إتاحة استخدام
│   │   ├── components.css  ← مكتبة مكوّنات BEM قابلة لإعادة الاستخدام (زر، بطاقة، توست..)
│   │   └── views.css       ← تخطيط خاص بكل عرض من العروض الستة
│   │
│   ├── js/
│   │   ├── data.js         ← كل المحتوى الثابت (المواد الكيميائية، التعليم، السلامة)
│   │   ├── state.js        ← إدارة الحالة المركزية + localStorage
│   │   ├── utils.js        ← دوال مساعدة عامة (بحث، توست، نسخ، تنسيق)
│   │   ├── router.js       ← التوجيه الداخلي (Hash Router)
│   │   ├── dashboard.js    ← منطق عرض لوحة التحكم
│   │   ├── chemicals.js    ← منطق عرض المواد الكيميائية
│   │   ├── education.js    ← منطق عرض الأكاديمية التعليمية
│   │   ├── safety.js       ← منطق عرض السلامة والطوارئ
│   │   ├── ai.js           ← منطق المساعد الذكي (محرك إجابة محلي، بلا خادم)
│   │   ├── settings.js     ← منطق عرض الإعدادات
│   │   └── app.js          ← نقطة الدخول الوحيدة (bootstrap فقط)
│   │
│   └── icons/               ← أيقونات PWA بكل الأحجام (عادية + maskable)
│
└── scripts/
    └── generate_icons.py    ← أداة تطوير محلية لتوليد الأيقونات (غير مُستخدمة في التطبيق نفسه)
```

### مبادئ معمارية أساسية

- **مصدر واحد للحقيقة لكل شيء**: بيانات المحتوى في `data.js` فقط، قيم
  التصميم في `tokens.css` فقط، حالة المستخدم في `state.js` فقط.
- **مسؤولية واحدة لكل ملف** (Single Responsibility): كل ملف JS يخدم غرضاً
  واحداً محدداً ولا يتداخل مع مسؤوليات ملف آخر.
- **لا متغيرات عامة (globals)**: كل شيء داخل وحدات ES Modules، الحالة محفوظة
  في إغلاق (closure) خاص بـ `state.js` ولا يمكن الوصول إليها إلا عبر دوال مُصدَّرة.
- **تفويض الأحداث (Event Delegation)**: كل عرض يستخدم مستمعاً واحداً على
  عنصره الجذر بدلاً من مستمع منفصل لكل بطاقة/زر متكرر.
- **BEM في كل مكان**: `.block`, `.block__element`, `.block--modifier` بلا استثناء.
- **توكنز دلالية فقط في المكوّنات**: `components.css` و `views.css` لا
  يشيران أبداً لتوكنز أولية (`--primitive-*`) مباشرة — فقط توكنز دلالية
  (`--surface-*`, `--brand-*`) تسمح بتبديل الوضع الداكن/الفاتح بلا أي تعديل
  على مستوى المكوّنات.

## 🎨 نظام التصميم

- **Material Design 3 + Glassmorphism**: خلفيات زجاجية (`backdrop-filter`)
  للرأس اللاصق وشريط التنقل والنوافذ المنبثقة.
- **هوية صناعية**: تدرّجات فولاذية داكنة، لهجة برتقالية للخطر (Hazard Orange)،
  خط `JetBrains Mono` لأسماء المواد الكيميائية بنمط "شريط اللاصق" الصناعي.
- **وضعان كاملان**: داكن (افتراضي) وفاتح، يُبدَّلان عبر `data-theme` على `<html>`.
- **حجم خط قابل للتحكم**: 4 مستويات من صفحة الإعدادات عبر `data-font-size`.
- **استعلامات الحاوية (Container Queries)**: تُستخدم في بطاقات المواد
  الكيميائية للتكيّف حسب عرض البطاقة نفسها لا عرض الشاشة، مع دعم احتياطي
  (`@supports`) للمتصفحات الأقدم.

## ♿ إتاحة الاستخدام (Accessibility)

- تنقّل كامل بلوحة المفاتيح، حالات `:focus-visible` واضحة على كل عنصر تفاعلي.
- حد أدنى 44×44px لكل هدف لمسي.
- سمات ARIA صحيحة (`aria-expanded`, `aria-current`, `aria-pressed`, `role="log"` للمحادثة).
- دعم `prefers-reduced-motion` و `prefers-contrast: more`.
- رابط تخطي المحتوى (`skip-link`) كأول عنصر في الصفحة.
- دعم الطباعة (`@media print`) لصفحات السلامة والتعليم.

## 📱 PWA — العمل بدون إنترنت

- **استراتيجية التخزين**: Cache First مع تحديث خلفي صامت.
- **قابل للتثبيت**: على الجوال (شاشة رئيسية) وسطح المكتب، عبر `manifest.json`.
- **اختصارات سريعة**: الوصول المباشر للمواد الكيميائية أو المساعد الذكي أو
  الطوارئ من قائمة أيقونة التطبيق المثبَّت (على الأنظمة الداعمة).

### تحديث نسخة الكاش بعد أي تعديل مستقبلي
عند نشر أي تحديث للتطبيق، **يجب** رفع رقم الإصدار في أعلى `service-worker.js`:
```js
const CACHE_VERSION = 'steward-guide-v2'; // كان v1
```
بدون هذه الخطوة، ستستمر الأجهزة التي زارت التطبيق سابقاً في استخدام النسخة
القديمة المخزَّنة مؤقتاً حتى لو كانت النسخة الجديدة منشورة على GitHub Pages.

## 💾 تخزين البيانات

كل بيانات المستخدم (المفضلة، السجل الأخير، تقدّم الأكاديمية، سجل المحادثة،
التفضيلات) محفوظة في `localStorage` تحت مفتاح واحد (`stewardApp:v2:state`).
لا توجد قاعدة بيانات، لا خادم، لا مزامنة سحابية — كل شيء محلي بالكامل على
جهاز المستخدم. صفحة الإعدادات توفّر تصدير/استيراد يدوي (ملف JSON) لنقل
البيانات بين الأجهزة عند الحاجة.

## 🔧 كيف تُضيف محتوى جديداً

### إضافة مادة كيميائية جديدة
أضف كائناً جديداً لمصفوفة `chemicals` في `assets/js/data.js` بنفس البنية
الموجودة — سيظهر تلقائياً في البحث والفلاتر والمساعد الذكي بلا أي تعديل آخر.

### إضافة وحدة تعليمية جديدة
أضف كائناً جديداً لمصفوفة `educationModules` في `data.js`، ثم أضف حالة
جديدة في دالة `buildModuleContent()` داخل `education.js` إن كان شكل
المحتوى مختلفاً عن الأنماط الموجودة (شبكة معلومات، خطوات، جدول..).

### إضافة عرض (صفحة) جديد بالكامل
1. أضف `<section class="view" data-view="اسمك" hidden></section>` في `index.html`.
2. أضف زر تنقّل مطابق بـ `data-nav-target="اسمك"` في `.bottom-nav`.
3. أنشئ `assets/js/اسمك.js` يستدعي `registerView('اسمك', { onEnter: ... })`.
4. استورد الملف الجديد في `app.js`.

## 🧪 التحقق من الجودة

تم التحقق من هذا المشروع آلياً قبل التسليم:
- فحص صياغة (syntax) لكل ملفات JavaScript.
- التأكد من تطابق كل الاستيرادات (`import`) مع تصديرات (`export`) فعلية.
- التأكد من أن كل قيمة `var(--token)` في CSS معرَّفة فعلياً في `tokens.css`.
- التأكد من تطابق أسماء العروض بين `index.html` وشريط التنقل ووحدات `registerView`.
- التأكد من أن كل ملف في قائمة التخزين المؤقت لعامل الخدمة موجود فعلياً على القرص.
