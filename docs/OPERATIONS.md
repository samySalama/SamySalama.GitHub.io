# دليل التشغيل والنشر (v2.3)

## 1) أول إعداد على GitHub (مرة واحدة)
1. ارفع المشروع كاملاً إلى المستودع (فرع `main`).
2. **Settings → Pages → Build and deployment → Source = GitHub Actions** (بدل Deploy from a branch).
3. أول push يشغّل `deploy.yml`: يفحص (ESLint، الأنواع، الاختبارات، E2E) ← يبني `_site` ← يضع رقم كاش جديداً ← يولّد QR ← Lighthouse ← ينشر. **لا يُنشر شيء إذا فشل أي فحص.**
4. التطبيق على `https://USER.github.io/REPO/` وملصقات QR على `/labels/qr-labels.html`.

لا حاجة بعد الآن لرفع `CACHE_VERSION` يدوياً (يُستبدل تلقائياً عند النشر). للتشغيل المحلي استعمل `npm run serve`.

## 2) حوكمة محتوى السلامة
- **`chemical-meta.js`**: لكل مادة `lastReviewed` (`YYYY-MM-DD`) و`sdsUrl` (https). القيم الابتدائية `null` عمداً — تظهر البطاقة «لم تُراجع مع صحيفة SDS بعد» حتى يُطابق مسؤول السلامة كل مادة مع الصحيفة الرسمية.
- **CODEOWNERS**: استبدل `@REPLACE_WITH_SAFETY_OWNER` باسم مسؤول السلامة، ثم فعّل في Settings → Branches قاعدة لـ `main` تتضمن *Require a pull request* و*Require review from Code Owners*. بدونها لا يُلزَم أحد بالمراجعة.
- **`npm run report:review`** يعرض النواقص (يظهر أيضاً في ملخص CI). أضف `-- --strict` لإفشاله عند وجود نقص حين تكتمل المراجعة.
- أي تعديل لنص تخفيف في `data.js` يُفشل اختبار `dilution.js` حتى تُحدَّث الحاسبة.

## 3) ملصقات QR
`npm run qr -- --base https://USER.github.io/REPO/ --out dist-qr` ثم افتح `dist-qr/qr-labels.html` واطبع (A4، 3 أعمدة). أو استعمل النسخة المنشورة تلقائياً. اختبر مسح عيّنة بجوال قبل الطباعة الجماعية.

## 4) اللقطات البصرية
أول مرة: Actions → **Visual snapshots** → Run workflow مع `update = true` (يولّد المرجعيات على Linux ويرفعها). بعدها شغّله بلا update لمقارنة أي تغيير.

## 5) الإصدارات
عدّل `version.js` و`package.json` و`CHANGELOG.md` ثم `git tag v2.3.0 && git push --tags` ← ينشئ `release.yml` إصداراً بملاحظات تلقائية.

## 6) نشر المستودع علناً — قائمة تحقق
- [ ] إدارة الفندق/الشركة وافقت على نشر إجراءات القسم وأسماء منتجات Ecolab وشعار Marriott.
- [ ] لا بيانات داخلية حساسة (أرقام داخلية، أسماء موظفين) في `data.js`.
- [ ] مسؤول السلامة راجع المحتوى (انظر 2).
- [ ] قرّرت: هل يُفهرس الموقع في محركات البحث؟ لمنعه أضف في `<head>`: `<meta name="robots" content="noindex, nofollow">`.
- [ ] مستودع **خاص** + Pages خاصة خيار متاح في بعض خطط GitHub إن لزم حصر الوصول على الموظفين.

## 7) الخصوصية
لا تتبع ولا تحليلات. بيانات المستخدم (مفضلة، تقدّم، سجلات، محادثات) في `localStorage` على جهازه فقط. التشخيص يعرض تقريراً يرسله الموظف بيده. سجلات الحرارة محلية — صدّرها CSV دورياً إن كانت جزءاً من توثيق رسمي (مسح بيانات المتصفح يحذفها).
